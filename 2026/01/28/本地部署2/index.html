实战记录（2）：Conda 环境隔离实战：本地部署 Xinference + LangChain-Chatchat

前言：为什么我们需要两个虚拟环境？

在本地搭建私有化 RAG（检索增强生成）知识库时，很多开发者会遇到一个典型的痛点——“依赖地狱” (Dependency Hell)。

简单来说，就是 “一山不容二虎”：

  • Xinference (后端推理) 说：“我需要 新版本 的 FastAPI 和 Gradio 才能工作。”
  • LangChain-Chatchat (前端应用) 说：“不行，我只能用 旧版本 的 FastAPI 和 Numpy 才能跑。”

如果你试图把这两个软件装在同一个 Conda 环境（比如 deep_learning）里，pip 在安装时就会“打架”，强制把高版本依赖降级，导致 Xinference 彻底坏掉。

解决方案：环境隔离（Conda Environment Isolation）

我们需要建立两个独立的“平行宇宙”：

  1. xinference_env：只跑后端模型，锁定 numpy<2.0，适配新版组件。
  2. chatchat_env：只跑前端 UI，适配旧版组件。

运行的时候，我们需要同时打开两个 Shell 窗口，左边跑后端，右边跑前端。

  • 注意：Windows 的命令行（CMD）默认使用 GBK (ANSI) 编码来显示中文，而你现在的 .bat 文件应该是用 UTF-8 格式保存的。

当 CMD 用 GBK 去读 UTF-8 的汉字时，就会出现乱码。更糟糕的是，乱码会吞掉部分命令字符（比如把 set CH 吞成了乱码，只剩下 ATCHAT_ROOT），导致程序运行报错。

  • 解决：用“记事本”另存为 ANSI 编码（推荐）不需要改代码，只需要改文件的保存格式。

  1. 右键点击你的 start_ai_system.bat 文件，选择 “编辑”（或者用记事本打开）。

  2. 点击左上角的 “文件” (File) -> “另存为” (Save As)。

  3. 在弹出的窗口最下方，找到 “编码” (Encoding) 选项。把它从 UTF-8 改为 ANSI。

  4. 点击 保存 并覆盖原文件。再次双击运行，乱码就会消失，命令也能正常识别了。
